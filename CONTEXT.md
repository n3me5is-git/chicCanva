# chicCanva AI-agent context

## Objective

chicCanva is a single-HTML, browser-based “mini Canva” for printable educational material. Chicca is the small teacher mascot; the current slogan is **“Piccole idee, grandi progetti.”** Preserve the one-HTML application, limited `file://` operation, richer HTTP(S) features, the dependency-free PowerShell launcher, and the deployable PWA bundle.

## Source-of-truth and build

Do not edit generated `chicCanva.html`, build copies, `tests/v7-test.html`, or `docs/user-guide.html` as the primary source.

Active modular sources:

- `development/workspace*` — multi-project/page model, special page macro, groups, rename/reorder/delete dialogs;
- `development/enhancements*` — toolbar/sidebar interaction and UI refinements;
- `development/image-effects*` — grayscale, Sobel outline, chroma key, automatic target color, canvas eyedropper;
- `development/final-upgrades*` — unified export, ZIP writer, page/region image export to the system clipboard, clipboard/URL/Puter integration, AI additions;
- `development/runtime-upgrades*` — two-finger canvas navigation and Puter authentication/account gates;
- `development/pdf-import*` and `development/vendor/pdf*` — local PDF page parsing/rasterization, embedded PDF.js display layer and worker;
- `development/version.json` — single source for the public application version; build date is generated by the composer;
- `development/clipart*` — Openclipart explorer and translation fallback;
- `development/pwa*` and `development/pwa/*` — PWA gate, install/update UI, manifest, service worker;
- `development/pending.js` — current persistence, undo/redo, emoji browser, and mobile background-removal overrides;
- `development/build-workspace.py` — authoritative composer.

Build and verify from the repository root:

```powershell
python development/build-workspace.py
python tests/build-v7-tests.py
python tests/check-chic-build.py
git diff --check
```

Then run `tests/v7-test.html` through HTTP with a fresh query string and require every visible test to pass through `ALL V7 CHECKS COMPLETE`.

## Important current behaviors

- One custom-page model; “one letter/group per page” is a special macro.
- Multiple projects stay open in tabs; imported JSON opens a new project.
- Every page has independent name, size, orientation, objects, and order.
- All sidebar cards start collapsed; single-section expansion is enabled by default.
- Text can be outline (transparent fill + configurable stroke) or filled.
- About 2,100 font metadata entries are embedded; font binaries load lazily.
- Smart emoji creates separate text/OpenMoji objects inside a separable group.
- OpenMoji has full browse/search/categories, color/black style, ink, and stroke width.
- Image operations preserve the original. Crop is non-destructive, previews excluded source areas translucently, and reset restores source geometry without changing its scale or proportions; other transforms create copies.
- PDF import is fully local: one/all source pages become PNG assets, each fitted without distortion onto an A4 portrait/landscape page. Destination can be a new project or append to the active one; quality is 1×–3×.
- Chroma-key automatic color detects the dominant perimeter color. Internal matching areas are removed by default.
- Every color input receives a canvas eyedropper. The picker samples the lower raster canvas using client-to-backing-buffer coordinates; do not replace it with Fabric document coordinates.
- IMG.LY background removal is local. Desktop reuses selectable models/session. Mobile forces `isnet_quint8`, downscales excessive input, uses a disposable worker, and releases RAM while retaining cached model files.
- Puter AI offers model/provider/quality/aspect/style/reference, chroma-key prompt injection, usage feedback, and optional local post-removal. AI controls stay hidden until explicit Puter sign-in; the account bar supports `request_auth` account switching and logout. Puter-assisted URL and Clipart actions use the same login modal. Generation always requires an explicit click.
- Canvas navigation supports Fit, numeric zoom, Ctrl+wheel, hand pan, and a two-touch pinch that zooms around the gesture midpoint while panning.
- Clipart searches public Openclipart pages, expects English keywords, optionally translates through MyMemory, and falls back to a compact internal didactic dictionary.
- Autosave uses stable IndexedDB `workspace-current`/`workspace-previous`, an immediate dirty marker, and small synchronous fallback. Startup can recover without a localStorage pointer.
- Export supports PDF, PNG, JPG, region, and client-side ZIP. JSON can optionally include history.
- PWA is offered only on public HTTPS domains, not file/localhost/IP/private hosts. Updates use a waiting-worker banner and explicit activation. Social metadata uses absolute URLs from `CHICCANVA_PUBLIC_URL` (default `https://chiccanva.testthis.one/`) so Telegram can crawl it without JavaScript.

## Non-negotiable implementation rules

1. Preserve the single application HTML and PowerShell-only launcher.
2. Keep existing functions unless the user explicitly replaces them.
3. Core editing must remain useful from `file://`; HTTP-only widgets are disabled with the exact user-oriented message.
4. Do not silently use Puter or another user-pays service.
5. Preserve image originals and editable project state.
6. Keep mobile memory safeguards.
7. Maintain stable DOM IDs and module injection order.
8. Update guide, README, docs, context, generated builds, and tests with material changes.
9. Do not delete or modify `.codex-remote-attachments/` or historical `old/` files unless explicitly requested.
10. Respect third-party licenses: original chicCanva code is MIT; PDF.js is Apache-2.0; embedded IMG.LY is AGPL-3.0; OpenMoji graphics are CC BY-SA 4.0; Openclipart works are declared public domain/CC0; Fabric/jsPDF/ONNX Runtime are MIT; fonts retain individual licenses.
11. Keep `development/version.json`, the generated build date, the in-app footer, documentation, root HTML, local build, and PWA build synchronized through `build-workspace.py`.

## Known architectural risks

- The application composer performs asserted string replacements on a large baseline; changed anchors fail the build.
- Feature modules wrap global functions, so injection order and exactly-once predecessor calls matter.
- One syntax error breaks the whole single HTML; Node inline syntax validation and browser tests are mandatory.
- Large Data URL assets/history can pressure browser storage and memory.
- PWA/CDN service-worker caching can present stale builds if the SW response is cached upstream.
- External services may be blocked by CORS, ad blockers, network policy, rate limits, or account state.
- Distributing/hosting the combined build requires attention to IMG.LY AGPL obligations and OpenMoji attribution/share-alike terms.
